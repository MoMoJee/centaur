# 部署验收与回退

当前阶段为升级准备。本页定义经授权后执行的候选版本验收。通用安装背景见[上游部署指南](../pages/deploying-in-production.mdx)，实例参数与证据位置按[运维入口](index.md)定位。

## 升级前

1. 取得 WSL 各层测试记录。确认旧镜像、候选镜像、Chart、API 与 Console 数据库、搜索后端、存储类和共享开关。记录镜像摘要及版本，核对 Kubernetes context 和 namespace。
2. 在隔离环境以旧版数据快照演练新增迁移。覆盖旧数据、既有默认会话、新对话键和重复启动，检验迁移锁时长并保留完整日志。
3. 确定可恢复的备份点，保存数据库与需保留的 PVC 数据，演练恢复并实测耗时。确定写入冻结窗口和切回的触发条件。共享开关默认关闭，待实例授权和旧路径冒烟通过后启用。

## 数据库和回退

采用增量迁移。历史记录保留在默认会话范围，新增 `conversation_id` 使用可空字段或独立关联。计划优先单独存储 opt-in 幂等键与指纹，保留上游 `session_executions` 默认幂等索引和活动执行约束。用外键和条件更新维护对话、执行及输出归属。沿用原搜索后端和旧迁移文件，沿 [SQLx 迁移入口](../../crates/centaur-session-sqlx/src/migrations.rs)核对新版本顺序和旧版本处理未知迁移号的行为。

- 回退触发条件包括迁移未通过、旧路径检查失败、对话错配、共享 Pod 被非预期暂停或回收，以及备份恢复演练失败。
- 触发时关闭共享入口，暂停新执行和写入，等待执行结束或按批准的策略终止，保存当前快照和归属证据。先用旧镜像和升级后的库快照实测启动、读写和默认路径。通过后按演练步骤切回旧应用。
- 若旧版不能读取升级后的库或拒绝未知迁移，按演练恢复升级前数据库及所需 PVC 快照，再启动旧版并跑旧路径冒烟。回退要记录冻结点和可恢复时间点，升级后写入由备份取证并按实例规则对账。原地改写 SQLx 迁移账本不属于回退流程。

## PVE 实测放行

| 门槛 | 需要留存的证据 |
| --- | --- |
| 升级前后可用 | 旧版基线和候选版的网页加载、登录、默认调用、完成执行和 SSE 回放均通过。记录版本及执行终态。 |
| 实际模型链路 | 通过配置的 NewAPI 完成真实 Codex 请求。记录 provider 标识和脱敏结果，核对凭据由受控配置注入。 |
| A → B → A | 使用目标网页，记录同一沙箱和 Pod UID、两个不同的 `threadId`、各自输出，以及文件、临装软件和进程标记。覆盖忙状态和断线重连。 |
| 生命周期与数据 | 越过隔离环境中配置的 idle pause 和短化的最大年龄窗口，确认共享 Pod 连续运行。另在独立维护窗口测试重建，确认 PVC 重挂、卷内文件及 Codex 状态恢复，并检查进程中断提示。 |
| 可回退 | 在匹配目标配置的隔离环境完成旧镜像切回或快照恢复，留存耗时和旧流程结果。 |

留存证据后根据触发条件放行或回退。一次性运行证据由实例服务卡定位，公共 changelog 记录可公开的结论与版本。
