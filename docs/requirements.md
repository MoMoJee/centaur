# 共享沙箱首版需求

首版面向一名已获授权的网页用户。沿用原有网页布局，在现有会话交互内切换逻辑对话。一个授权父会话使用一个持续运行的沙箱，逻辑对话 A、B 分别拥有 Codex `threadId`，使用固定的 NewAPI provider。

| 场景 | 可观察验收 |
| --- | --- |
| A → B → A | A 写入工作文件、临时安装测试软件并启动带标记的长驻测试进程。B 能读取文件和运行该软件。切回 A 后文件内容、软件版本、进程标记和进程启动时间相同。全程记录同一沙箱和 Pod UID。 |
| 对话归属 | A 两轮使用相同 `threadId`，B 使用另一个 `threadId`。A、B 的消息、执行、输出及 SSE 回放各自归属，页面切换后能返回并补齐各自输出。 |
| 串行执行 | A 正在运行时，在 B 发起新执行得到明确忙状态和可重试提示。A 终态后可重试。steer 与 interrupt 只作用于服务器核验过的目标执行。 |
| 网络重试 | 同一逻辑对话的同一幂等键和相同输入返回同一执行。不同输入复用同键得到冲突。另一逻辑对话可独立使用同一键。SSE 断线从最后事件游标重放。 |
| 默认调用 | 请求省略 `conversation_id` 时，原调用者的授权、执行、幂等、事件和生命周期行为回归通过。 |
| 空闲与失效 | 共享模式跨过配置的单轮空闲期限及回收测试期限仍保有已观测的 Pod 和进程。Pod 被替换时提示运行状态中断，持久状态按[卷边界](architecture.md#运行生命周期)验证。 |

首版共享同一沙箱内的文件、软件和进程。逻辑对话隔离范围是 API 授权和 Codex 历史、执行与输出归属。同一沙箱内的文件与进程由获授权的同一用户共享。跨用户共享、并行执行和 provider 切换留待另行设计。
