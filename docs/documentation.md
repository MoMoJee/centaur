# 文档维护

## 工作循环

1. 在 [plan](plan/index.md) 建立日期和顺序编号的计划，列出范围、依赖、验证和回退点。
2. 阅读最近的 `AGENTS.md`，在计划范围内实施。对照源码、测试和实际运行结果更新受影响的事实页。
3. 按 [changelog](changelog/index.md) 记录已完成的改动、验证证据与剩余项目。对未执行的测试写明状态和责任方。
4. 提交前查看完整 diff、检查 Markdown、相对链接和公开信息。按根目录 [AGENTS](../AGENTS.md) 的约定提交。

## 内容归属

需求、架构、开发和运维页记录当前契约与可用入口。方案讨论与验收条件放计划，已完成的变动与验证结果放在变更记录。给 fork 新增的页面从[索引](index.md)接入，每页一个一级标题，标题、列表、表格和代码块分开，代码块标语言。上游文档站内容仍在 `docs/pages`。

新增公共文档使用项目相对路径与中性标识。部署地址、账户、凭据、实例参数和现场证据由独立运维知识库的服务卡定位及管理。提交前检查新增内容是否含内网域名、真实地址、绝对主机路径、真实用户名、凭据或私有仓库标识。
