# 共享沙箱首版实施计划

状态为待实施。基线为 `v2026.11.13`，需求与设计见[需求](../requirements.md)和[架构](../architecture.md)。

## 1. 固定基线和入口

- 先完成 [WSL 基线](../development.md)，记录提交、工具版本、命令、退出状态和跳过项。用同一组输入在基线和候选版本对照旧 API。
- 沿现有网页发送、回放和控制动作追到 API，记录实际页面、请求形状及授权来源。上游 Console 是管理 SPA，docs 也有演示面板。以目标页面真实链路为接线依据，保持其布局。
- 上游 [PR #2273](https://github.com/paradigmxyz/centaur/pull/2273) 于 2026-11-18 核对为 open。参考其解析 `thread/started` 与恢复线程 ID 的接线。本阶段未引入该 PR。实施时用父会话和逻辑对话确定映射，避免沿用单一会话级恢复 ID 或在恢复失败时无提示开启新线程。

## 2. 持久模型与 API

- 增加父会话与逻辑对话映射，及可关联到逻辑对话的执行记录。先写迁移和回退用例，再接存储与 API。保留历史的默认桶，保持旧幂等键语义。
- 给 opt-in 请求补充范围校验、请求指纹、执行记录与单沙箱执行锁。在派发前提交持久执行记录及其归属。补齐重试、授权失败、重复提交、跨对话控制和重启恢复用例。
- 先验证空库与旧快照升级，保留已应用迁移和搜索后端。按[部署门槛](../operations/deployment.md)实测同库旧版本启动或恢复快照的回退路径。

## 3. Harness、生命周期与网页

- 在 Codex blocks 输入及可信事件归一化层加入执行关联。用 fake app-server 覆盖首次创建、A/B/A 切换、恢复失败、旧通知晚到、interrupt、steer 和 transport 断开后的执行归属。
- 加入显式共享沙箱 keepalive，分别覆盖 idle pause、按年龄回收、运维主动停止及故障重建。用同一 Pod 内的工作文件、临装软件与进程，验证空闲和切换后连续运行。
- 在既有页面接入逻辑对话选择和按执行订阅。验证开始、重连、切换、忙状态和失败提示。配置并锁定 NewAPI provider，按[开发指南](../development.md)执行组件、数据库、集群和浏览器测试。

## 4. 升级验收

- WSL 通过后才进入 PVE 环境验证。使用批准的候选产物和实例配置，按[部署验收与回退](../operations/deployment.md)记录 Pod 身份、PVC 重挂、网页及 API 证据和回退耗时。
- 所有首版验收项都有证据后更新事实文档和变更记录，再完成对应阶段的提交。
